SIWA is primary
Sign in with Apple is the first and most prominent action — required for App Store. Email/OTP is the fallback. SIWA skips screens 2–3 entirely and drops directly into Screen 4 (welcome) or Home if returning user.
Screen height
The dark hero hero gradient fills ~200px and the form lives below. On the physical phone this creates breathing room without wasted space.
Auto-confirm from email
Supabase can auto-fill the OTP if the user taps the link in the email rather than typing the code. The 6-box UI is the fallback. Show a "Code sent — or tap the link in your email" hint above the boxes.
Countdown timer
OTP expires in 10 minutes. Show a countdown. On expiry, gray the boxes and show "Code expired — Resend" prominently.
New users only
Returning users (email already in Supabase) skip this screen and land on Screen 4 (welcome back) or directly on Home if the welcome has been seen before.
SIWA name handling
Apple only provides the user's name on the first SIWA login. After that it's gone. Pre-populate the name fields from the Apple identity token on first registration; Surface this screen even for SIWA users if name is blank.
Transition moment
This screen exists to punctuate the auth flow. It should animate in (fade + subtle scale up of the check circle) and auto-advance after ~1.5s if the user doesn't tap. Gives the backend time to finish account setup before Home loads.
First home
New users always see the empty state (no groups). Returning users land wherever they left off in the home context cycle — the app resumes their state.
Group creation is the gate
The paywall should appear here — before the group creation form, not after. Show what they get (meal planning + voting) then ask for subscription. Free users can browse recipes but not plan.
Design decisions
Dark hero on a warm-canvas app
The login and welcome screens use a deep warm-dark background — not the app's default canvas. This creates a deliberate threshold feeling: you're stepping into the app from the outside. The warmth in the gradient (burnt orange at the bottom corner) keeps it from reading as generic and connects to the orange accent used throughout.
No password, ever
The auth model is SIWA or email OTP — there's no password creation, no confirm password field, no forgot password flow. This is intentional and worth protecting as the app grows. Passwords add friction, support burden, and security surface. OTP via Supabase is already implemented and working.
Open: paywall placement
Currently leaning toward gating group creation. But the better experience might be: let a new user create one group for free (demonstrate value first), then gate on second group or on advanced features. Worth testing both. The key principle: don't show a paywall before you've shown the user anything worth paying for.
Open: profile photo
Screen 3 shows a photo picker button on the avatar. Avatar initials are fine for V1. A photo option adds significant surface area (upload, resize, storage on S3, display throughout the app). Defer until AWS photo infrastructure ships — task #21.
