Sheet content
Shows group name, inviter's name, current member count, meals/week default, and recipe library size. Enough context to make an informed decision before joining. No app tour, no permissions gate — just one tap.
Success → auto-advance
After 1.5s the success screen auto-advances to the home screen with the new group already selected. The "Go to The Smiths →" CTA lets impatient users skip the wait. A NEW badge on the group pill reinforces which group was just joined.
Notification to inviter
Claire receives a push notification: "Andrew joined The Smiths." Sent server-side when the member row is created. No in-app action needed from Claire.

Auth gate — intent preserved
The invite token is stored locally before auth begins. After sign-in completes, the join fires automatically — the user never has to tap the link again. If they abandon auth, the token is discarded; they tap the link again when ready.
Expired = 410 Gone
The API returns 410 Gone for expired or used tokens (not 404 — the distinction matters: 404 means the link never existed, 410 means it did but is now consumed). The client shows this sheet for any non-200 response from the join endpoint.
Already a member
Handled as a soft success — the user is in the right place, they just don't need to join again. The CTA deep-links into the group directly. No error language, no friction.
Token lifecycle
Tokens are single-use and expire after 7 days. The owner can generate a new token at any time from the group settings share sheet — the old token is not invalidated, it just expires naturally. There is no revocation endpoint in V1; if a link is accidentally shared publicly, the owner can remove the unwanted member after the fact.
Deep link URL structure
Universal link: menuapp.com/join/{token}. Falls back to a web page with an App Store badge if the app isn't installed. The web page also stores the token in localStorage so it survives the install → open cycle on first-time installs.
Not-installed path
Tapping the link on a device without the app goes to a web landing page: group name, member avatars, "Download MenuApp to join." After install and first sign-in, the app checks for a pending invite token in the universal link and fires the join automatically. This requires Associated Domains entitlement + apple-app-site-association file on the server.
Sheet vs. full screen — original intent
The original design used a bottom sheet overlay to keep the home screen visible underneath. This was revised during implementation — see "As Built" notes below.
✓ As Built — full-screen route
Implemented as a dedicated route at /join/:token, not a bottom sheet. The route is public (bypasses auth redirect), so unauthenticated users can see the group preview. On join success, context.go('/groups/:groupId') replaces the join screen immediately — no celebration state.
✓ As Built — URL scheme
Using custom URL scheme menuapp://join/{token} for now (registered in Info.plist). Universal links (menuapp.com/join/{token}) require Associated Domains + apple-app-site-association on the production server — blocked on task #73.
✓ As Built — error states
InviteErrorKind enum handles 4 cases: expired (410 → dismiss only), alreadyMember (409 → "Go to Groups" CTA), notFound (404 → dismiss), network (retry button). Each maps to a distinct error message in _ErrorView.
✓ As Built — invite sharing surface
The share UI lives in group_members_screen.dart as _InviteSection. It auto-fetches (or creates) the invite on screen load, shows a copyable link pill, expiry time, a "Share invite" button (iOS share sheet via Share.share()), and a refresh button.
