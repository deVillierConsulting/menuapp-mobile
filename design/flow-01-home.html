The hook — design priority
This is the state most active users see on open. It must be instant and satisfying. Swipe right to approve, left to skip. No tap required — the gesture IS the vote.
Progress indicator
Shows personal vote progress only ("3 of 8"), not household totals — reduces social pressure to vote a certain way.
Trigger
User has voted on all recipes. At least one other member still has uncast votes.
Nudge action
"Remind Claire →" sends a push notification (task #42). Should feel casual, not nagging — rate-limited to once per day per recipient.
Cycle completion
The week feels resolved. "Go shopping →" routes to the Shop tab with the grocery list pre-loaded. "Plan next week" restarts the cycle — keeps momentum going.
Day assignment
Day-of-week labels ("Monday", "Wednesday") are a future enhancement — see calendar UI task #TBD. For now, ordering reflects vote score.
Design decisions
Why Home, not Groups
The previous Groups tab organized the app around management. Most users have one group. Making them navigate Group → Menu → Vote on every open added 2–3 unnecessary taps before they could do anything meaningful. Home is context-aware: it shows the most relevant action for where the user is in the planning cycle, with no navigation required.
Group switcher — multi-group users
The "House ▾" pill in the header is a lightweight group switcher. Tap to open a compact sheet listing all groups. The app remembers your last active group across sessions. Multi-group users are a minority — the switcher should feel secondary, not prominent.
Open: swipe vs. button voting
State 3 shows explicit approve/skip buttons. The existing implementation has swipe-to-vote already. The home screen version should use swipe — more satisfying, faster, and the card stack metaphor is familiar. Needs a subtle swipe hint on first use (e.g., a brief card tilt animation on load).
Open: monetization gate placement
Group creation is the proposed paywall boundary. State 1 is where most new users will encounter it. The CTA copy ("Create your first group") needs to feel like an invitation, not a purchase decision. Consider showing a value prop screen before the paywall — show what a finalized menu week looks like before asking for payment.
